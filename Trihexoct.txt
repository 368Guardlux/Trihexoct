! ║ §P — FINGERPRINT SURFACE REDUCTION: SAFE SUBSET + THE ACTUAL BEST FIX     ║
! ╚═══════════════════════════════════════════════════════════════════════════╝
! Read this before anything else in this section. The original list aborted
! Canvas/WebGL/AudioContext reads outright. That's the wrong tool: a page that
! calls canvas.toDataURL() and gets a thrown exception LOOKS DIFFERENT from a
! normal browser — "throws on canvas read" is itself a fingerprintable signal,
! and a rare one, so it can make you MORE identifiable, not less (same logic
! as §3.6 in the companion privacy-filters list: an uncommon signature stands
! out more than a common one, even if the uncommon signature is "hardened").
! It also just breaks legitimate canvas/WebGL/audio use outright — image
! editors, browser games, audio tools, video call background blur.
!
! The technique that actually works is NOISE, not blocking: return a plausible
! but slightly randomized value so the fingerprint is inconsistent across
! visits, without breaking the API. That's what Brave's fingerprinting
! protection and Firefox's privacy.resistFingerprinting do natively, properly
! tested against real sites — turn those on instead of hand-rolling it:
!   • Firefox: about:config → privacy.resistFingerprinting = true (note: also
!     changes timezone/locale reporting and rounds many timing APIs — read
!     Mozilla's docs on it before enabling, it's a broad setting).
!   • Brave: brave://settings/shields → Fingerprinting blocking → "Strict"
!     (may need occasional per-site relaxing if a specific site breaks).
!

! raw hardware-access APIs almost no legitimate site needs, already gated
! behind a permission prompt anyway, so blocking proactively removes a
! fingerprint vector with near-zero functional cost:
