# Trihexoct Guardlux operations runbook — v1.3.2

## Routine operation

- The GitHub Actions workflow attempts a refresh every 12 hours and after source/configuration changes. GitHub may delay scheduled jobs.
- The workflow runs the offline regression suite, fetches approved HTTPS reference feeds, checks source health and rolling feed-count anomalies, reconciles conservative overlap, validates the rendered list, and writes a build report.
- A successful job commits the generated `Trihexoct.txt`, manifest, source inventory, rolling feed baseline, and rule-delta report.
- Brave should continue subscribing to the same raw URL: `https://raw.githubusercontent.com/368Guardlux/Trihexoct/main/Trihexoct.txt`.

## If a feed-count anomaly stops the build

1. Open the `trihexoct-build-report` artifact and inspect the named feed's historical counts, current count, hash, response size, and error details.
2. Check whether the upstream project intentionally changed format or scope. Do not approve a change merely to make the workflow green.
3. If the change is legitimate, manually dispatch the workflow with **Accept feed-count anomaly** enabled. This override does not bypass required-feed, group, policy, or output validation gates.

## If the output-delta gate stops the build

1. Open `reports/rule-delta.json` from the failed run artifact. Review the number and examples of added/removed active rules and the `changed_ratio`.
2. Compare removals with the reference feed(s) responsible for coverage. Large reductions may be legitimate if trusted subscriptions already cover the same rule, but the report must support that conclusion.
3. If the change is understood and acceptable, manually dispatch the workflow with **Accept large output change** enabled. This is separate from feed-anomaly approval.
4. If the change is unexplained, do not override; fix the feed registry, source modules, or overlap logic and rerun tests.

## If a source fails or the list looks wrong

- Required feed failure, insufficient healthy feeds, policy violations, malformed output, and failed category gates must stop publication.
- The output-delta gate is evaluated before replacing the last-known-good list. Failed gates must not advance the feed baseline.
- A report generated by an offline build must say `OFFLINE BOOTSTRAP`; do not claim live reconciliation until an online workflow succeeds.
- Never turn a complete URL indicator into a domain-wide block without separate evidence. The OpenPhish feed remains health-only.

## Browser compatibility checks

After a new list is published, verify normal search, video playback, sign-in, checkout/payment, downloads, and embedded content on frequently used sites. If a legitimate feature breaks, report the exact URL, browser version, time, and relevant blocked request/rule; avoid sharing account tokens or private URLs. Disable the list temporarily if needed, then fix the specific rule in its source module.

## Security boundaries

The list is declarative filtering, not antivirus and not an AI that observes subscribers. Feed contents are untrusted input, are never executed, and are not copied wholesale into output. Keep Brave's own security protections and maintained lists enabled.
