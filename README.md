# Trihexoct Guardlux

**Project version:** 1.3.2  
**Published artifact:** `Trihexoct.txt`  
**Target engine:** Brave Shields (adblock-rust / ABP-style filter syntax)  
**Update model:** GitHub Actions attempts a rebuild every 12 hours and on relevant source/configuration changes, with concurrent reference-feed checks, rolling source-count anomaly gates, conservative overlap reconciliation, workflow-YAML validation, regression tests, and guarded publication.

Trihexoct is a supplementary filter list. It does not replace Brave's maintained filters, other trusted subscriptions, DNS filtering, or Microsoft Defender. Its goal is to provide a curated layer of third-party ad, measurement, attribution, cryptojacking-indicator, and explicit ad-slot coverage while adapting away rules that approved references demonstrably cover.

## How the automatic pipeline works

1. GitHub Actions attempts a build every 12 hours and when relevant source/configuration files change.
2. The workflow validates both workflow files, checks all required project files, and runs the offline regression suite.
3. Approved HTTPS feeds are fetched concurrently with bounded retries. Their contents are treated as untrusted text and are never executed or copied wholesale into the published list.
4. The builder removes a local rule only when it establishes exact overlap, a compatible host rule, or a recognized URL-parameter match from a successfully fetched and validated feed.
5. Feed-count anomalies are compared with a rolling median. A suspicious change stops the build until a maintainer reviews the report and manually approves the anomaly.
6. The output-delta gate stops publication if the candidate changes more than 40% of the previous active rule set, unless a maintainer separately approves the reviewed delta.
7. The rendered candidate passes internal policy, category-floor checks, manifest checks, and the static validator before the publisher commits the generated list and baseline.

This is deterministic automatic maintenance, not machine learning. The new threat intelligence comes from maintained reference feeds and reviewed module changes.

## Project layout

- `Trihexoct.txt` — generated Brave subscription list; do not edit by hand.
- `Trihexoct.meta.json` — output checksum, source hashes, project version, and published/effective category counts.
- `VERSION` — canonical project version.
- `src/modules/*.txt` — reviewed filtering rules organized by purpose.
- `config/reference_feeds.json` — approved HTTPS references, formats, size limits, and policy settings.
- `tools/build_filter.py` — reference fetching, overlap reconciliation, anomaly and output-delta gates, atomic publication, and reports.
- `tools/validate_filter.py` — static rule-policy and manifest-integrity validator.
- `tools/audit_source_modules.py` — deterministic source inventory, per-module hashes, duplicate detection, and policy audit.
- `tools/validate_workflows.py` — YAML syntax, duplicate-key, top-level-key, and workflow-step structure checks.
- `tools/write_summary.py` — build-report summary formatter used by GitHub Actions.
- `requirements-ci.txt` — CI-only YAML-parser dependency; the filter builder itself uses only the Python standard library.
- `tests/` — offline policy, source, feed, delta-gate, and workflow regression tests.
- `.github/workflows/main.yml` — scheduled/manual/push-triggered build and guarded publisher.
- `.github/workflows/test-pr.yml` — read-only pull-request validation.
- `reports/` — offline bootstrap report, rolling reference baseline, inventory, rule-delta report, initial audit, and coverage policy.
- `docs/OPERATIONS_RUNBOOK.md` — operations, manual gates, failure recovery, and browser-compatibility checks.

## Installation and first live run

1. Download and extract the complete v1.3.2 project ZIP.
2. Back up your existing repository files.
3. Upload/commit **the complete project contents** to `368Guardlux/Trihexoct` on branch `main`, preserving `.github/workflows/`, `config/`, `src/`, `tools/`, `tests/`, `docs/`, and `reports/`. Do not upload only `main.yml`; the workflow requires its matching Python scripts, feed registry, source modules, tests, manifest, and version file.
4. In Settings → Actions → General → Workflow permissions, allow GitHub Actions to read/write repository contents. The write permission is scoped to the publishing job and is used only after checks pass.
5. Open Actions → **Build and validate Trihexoct** → Run workflow. Review the `trihexoct-build-report-*` artifact.
6. Do not consider the list fully reconciled until a live run succeeds and the report confirms successful feed checks. If the feed-anomaly or output-delta gate fails, review the report before using a manual override.

After a successful run, Brave can keep using the existing raw URL. The subscription URL does not change when `Trihexoct.txt` is updated.

## Local validation

Requires Python 3.12+ and the CI-only dependency listed in `requirements-ci.txt` for workflow YAML checks:

```bash
python -m pip install -r requirements-ci.txt
python tools/validate_workflows.py
python -m unittest discover -s tests -v
python tools/audit_source_modules.py --output /tmp/trihexoct-source-inventory.json
python tools/build_filter.py --output /tmp/Trihexoct.txt --report /tmp/bootstrap-build-report.json
python tools/validate_filter.py /tmp/Trihexoct.txt
```

A live reference reconciliation is run in GitHub Actions and was successfully completed in this environment. The bundled `Trihexoct.txt` is now marked `ONLINE RECONCILIATION`, and the generated report confirms that all configured feeds passed validation.

## Scope and limitations

- Rules apply automatically once Brave fetches the list, but the file cannot inspect user browsing or independently learn new threats.
- Network rules are third-party scoped wherever possible; they may still affect embedded widgets or features served by third-party endpoints.
- URL-indicator feeds are used only for source health unless their format and policy explicitly allow safe coverage indexing; a malicious URL is not treated as evidence to block its entire host.
- Static validation is not a full Brave engine parse or live-site compatibility test. Keep backups and test login, video, search, shopping, and payment flows after updates.
- This is not antivirus software and cannot certify a website or download as safe.
